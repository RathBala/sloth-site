# Meta Pixel (marketing site → web app signup)

The landing page loads the [Meta Pixel](https://developers.facebook.com/docs/meta-pixel) so paid social (Facebook / Instagram) campaigns can measure visits, high-intent clicks to the app, and—once implemented on the app—completed registrations.

## Configuration

### Environment variable

The browser reads `window.__SLOTH_META_PIXEL__` from a **generated** file, [`src/assets/js/meta-pixel-config.js`](../src/assets/js/meta-pixel-config.js) (gitignored). Do not edit that file by hand.

1. In **Meta Events Manager**, create or select a Pixel and copy its **Pixel ID** (numeric).
2. In the repo root **`.env`**, set:

   - **`META_PIXEL_ID`**: the numeric Pixel ID (e.g. `123456789012345`).

3. Run **`yarn meta:config`** (also runs automatically before **`yarn dev`** and **`yarn build`**).

On **Netlify**, add **`META_PIXEL_ID`** under Site settings → Environment variables. The build runs `yarn build`, which generates `meta-pixel-config.js` before compiling CSS.

If `META_PIXEL_ID` is missing or invalid, the Pixel does not load and a console warning is logged (`[meta-pixel-analytics]`).

## Events (this site)

| Event / call              | When                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------ |
| `PageView`                | After `fbq('init')` on each landing page load                                                    |
| `ViewContent`             | Once per load (`content_name`: `sloth_landing`)                                                  |
| `Lead` (standard)         | User clicks a **signup** CTA (`data-analytics-cta` without `sign-in`) to `budget.slothmoney.app` |
| `AppSignInClick` (custom) | User clicks a **sign-in** CTA to the app                                                         |

`Lead` and custom events include `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content` from the **current landing URL** when present.

CTA placements are the same as in [PostHog funnel docs](./posthog.md#custom-events-funnel) (`hero-start`, `pricing-start`, etc.).

## Full funnel: account creation on the app

`Lead` here means “clicked through to start signup,” not “account exists.” For Meta to optimize and attribute **completed signups**, the **budget web app** (`budget.slothmoney.app`) should also load the **same** Pixel and fire a standard event when registration succeeds, typically:

- **`CompleteRegistration`** — after the user successfully creates an account (see [standard events](https://developers.facebook.com/docs/meta-pixel/reference#standard-events)).

Pairing browser Pixel with the [Conversions API](https://developers.facebook.com/docs/marketing-api/conversions-api) on the server is optional but often improves measurement; that lives in the app or backend, not this repo.

## Privacy / consent

If you serve users in regions that require consent before advertising cookies, integrate your cookie/consent banner with Meta’s guidance (e.g. consent mode) before scaling paid traffic. This repo does not implement a CMP.

## Local verification

1. Set `META_PIXEL_ID` in `.env` and run `yarn meta:config` (or `yarn dev`).
2. Open the site with test UTMs, click **Start for free**.
3. In Events Manager → **Test events** (or browser **Meta Pixel Helper** extension), confirm `PageView`, `ViewContent`, and `Lead` (with `content_name` matching the CTA id).
